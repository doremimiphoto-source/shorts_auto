### [C-01] Temu Product Feed API 존재하지 않음

**문제**
> 요구사항에 "Temu 어필리에이트 Product API" 명시
> → Temu는 **공식 제품 피드 API를 제공하지 않음** (2026년 6월 기준)
> 어필리에이트 프로그램은 있으나, 자동화된 제품 데이터 수집은 공식 미지원

**영향**: V1 버티컬 자동화 전체 불가

**해결책 (선택)**
```
Option A (권장): Temu 웹 크롤링
  → robots.txt 확인 후 준수 범위 내 크롤링
  → 제품명·가격·이미지 URL·어필리에이트 링크 수집
  → 리스크: Temu 정책 변경 시 크롤러 수정 필요

Option B: AliExpress Portals API 중심으로 전환
  → AliExpress는 공식 Affiliate Product Feed 제공
  → 테무 단독 대신 "알리 + 아마존 비교"로 콘텐츠 각도 조정

Option C: 제품 수동 큐레이션 DB
  → 주 1회 수동으로 제품 30~50건 DB에 등록
  → 자동 생성 파이프라인은 DB에서 랜덤 선택
  → 완전 자동화 아니지만 가장 안전
```

**요구사항 수정 필요**: §2-1-3 데이터 소스 표 수정

### [C-02] Amazon PA-API — 초기 계정 접근 불가

**문제**
> Amazon Associates + PA-API 5.0 접근 조건:
> 1. 가입 후 **180일 이내 3건 이상** 실적 발생해야 계정 유지
> 2. PA-API는 Associates 계정에서 **최소 실적 요건** 충족 후 부여
> → **초기 트래픽 없는 신규 계정은 API 접근 자체 불가**

**영향**: V1 Amazon 가격 비교 자동화 초기 불가

**해결책**
```
단기 (1~3개월):
  Amazon 제품 링크를 수동으로 수집 (개발자 없이도 가능)
  → amazon.com 제품 URL에 Associates 태그 파라미터 수동 추가
  → 크롤링 없이 링크만 DB에 미리 등록

중기 (3개월+, 실적 요건 충족 후):
  PA-API 5.0 정식 연동 → 가격 자동 수집 활성화

대안:
  Rainforest API (Amazon 비공식 래퍼) → 무료 플랜 존재하지만 제한적
```

**요구사항 수정 필요**: §2-1-3 "Amazon PA-API 초기 제한 사항" 명시

### [C-03] Instagram Graph API — 이미지 직접 업로드 불가

**문제**
> Instagram Graph API 캐러셀 업로드 방식:
> 1. 각 이미지를 **HTTPS로 접근 가능한 외부 URL**로 업로드 (로컬 파일 직접 전송 X)
> 2. 즉, 생성된 카드 이미지를 먼저 **외부 서버에 호스팅** 후 URL 제출 필요
>
> 현재 요구사항에 이미지 호스팅 인프라가 정의되어 있지 않음

**영향**: Instagram 자동 업로드 전체 구현 블로킹

**해결책 (선택)**
```
Option A (권장 — 무료): Imgur API
  → 생성된 이미지 → Imgur 무료 업로드 → HTTPS URL 획득
  → Imgur 클라이언트 ID 발급 (무료)
  → 장점: 완전 무료, 구현 간단
  → 단점: 링크 만료 가능성 (보통 만료 없음)

Option B: GitHub Pages / GitHub Raw
  → 이미지를 GitHub 저장소에 push → raw URL 사용
  → 장점: 영구 보관, 무료
  → 단점: 저장소 용량 증가, push 속도

Option C: Cloudflare R2 (무료 플랜)
  → 무료 10GB/월 + 무료 GET 요청 1,000만회
  → 장점: 프로덕션급, HTTPS URL, 속도 빠름
  → 단점: 계정 설정 필요
```

**요구사항 추가 필요**: §6-1에 "이미지 임시 호스팅" 인프라 항목 추가

### [C-04] TikTok Content Posting API — 이미지 슬라이드쇼 미지원 가능성

**문제**
> TikTok Content Posting API 현실:
> 1. 일반 개발자 승인: 2~4주 소요 + 비즈니스 계정 필수
> 2. **이미지 슬라이드쇼 (Photo Mode) API는 현재 제한적 지원**
>    → 2026년 기준 모든 계정/지역에서 자동화 가능한지 확인 필요
> 3. API 승인 이후에도 일일 업로드 한도 존재

**영향**: TikTok 자동 업로드 불확실성 높음

**해결책**
```
단기 (API 승인 대기 중):
  Buffer 무료 플랜 활용 (3개 채널, 월 10건)
  → 한계: 완전 자동화 아님 (수동 예약)

중기 (API 승인 후):
  TikTok Content Posting API → 슬라이드쇼 업로드 테스트
  → Photo Mode 가능 여부 실제 확인 후 구현

대안 (API 불가 시):
  TikTok 영상 자동화 (이미지 슬라이드 → MP4 변환 후 업로드)
  → FFmpeg로 이미지 시퀀스 → 영상 변환 (기존 파이프라인 재활용)
  → Video API는 더 광범위하게 지원됨
```

**요구사항 수정 필요**: §3-2 TikTok 섹션에 리스크 및 대안 명시

### [C-05] K-뷰티 크롤링 법적 위험 (올리브영·지그재그·에이블리)

**문제**
> 요구사항 §2-3-3에 올리브영·지그재그·에이블리 "웹 크롤링" 명시
> → 국내 플랫폼 대부분 이용약관에 **자동화 수집 명시적 금지** 조항 포함
> → 특히 올리브영: 무단 크롤링 시 법적 조치 사례 있음
> → 지그재그·에이블리: App 전용 트래픽, 웹 크롤링 실효성도 낮음

**영향**: V3 데이터 소스 전면 재설계 필요

**해결책**
```
안전한 대안 (법적 리스크 0):

1. 네이버 쇼핑 검색 API (공식, 무료 25,000 req/일)
   → 브랜드명 + 카테고리 검색 → 제품 정보 수집
   → 완전 합법, 이미지·가격·링크 제공

2. 올리브영 공식 파트너 프로그램 가입
   → 파트너 승인 후 상품 데이터 공식 제공
   → 가입 조건: 사이트/SNS 계정 운영 실적 필요

3. YesStyle / StyleKorean Affiliate Feed (글로벌)
   → 공식 제품 피드 제공 (어필리에이트 가입 후)
   → 국내 제품도 포함됨

4. LLM 기반 K-뷰티 정보 생성
   → 실제 크롤링 없이 "한국 SNS에서 바이럴 중인" 스타일로 LLM 생성
   → 구체적 가격은 LLM 생성값 대신 네이버 API로 실시간 검색

최종 데이터 소스 재정의:
  크롤링 제거 → 네이버 쇼핑 API + YesStyle API + LLM 생성 조합
```

**요구사항 수정 필요**: §2-3-3 데이터 소스 전면 교체

### [M-04] LLM 생성 콘텐츠 사실 오류 리스크

**문제**
> 여행지 정보·제품 비교를 LLM으로 자동 생성 시
> 가격·거리·개방 여부 등 오래된/부정확한 정보 생성 가능
> → 사용자 불만, 신뢰도 하락, 최악의 경우 플랫폼 신고

**해결책**
```
V2 (여행지):
  → 검증 가능한 사실은 LLM이 아닌 실시간 API로 조회 (Booking.com 가격)
  → "always verify before travel" 면책 문구 카드에 삽입
  → LLM 프롬프트: "검증 불가능한 구체적 수치 사용 금지" 지시

V1 (가격 비교):
  → 가격은 반드시 실시간 API/크롤링으로 수집 (LLM 생성 금지)
  → "가격은 변동될 수 있음" 면책 문구 삽입

V3 (K-뷰티):
  → 제품명·가격은 네이버 쇼핑 API로 실시간 조회
  → 효능 설명만 LLM 생성 사용
```

### [M-05] Linktree 무료 플랜 — 분석 기능 없음

**문제**

  예) ?utm_source=instagram&utm_medium=carousel&utm_campaign=v1_temu
  → Google Analytics (무료)에서 UTM별 클릭 집계
  → 또는 Plausible.io 무료 플랜 (1만 PV/월)

Linktree 대안:
  Carrd.co (무료) — 단순 랜딩 페이지로 링크 허브 구성
  → 더 많은 커스터마이징 가능
```

### [L-02] 카드 비율 변환 — 단순 리사이즈 불가

**문제**

  render_vertical()   → 1000×1500 (Pinterest)
  render_story()      → 1080×1920 (TikTok)

```
